# cvehunt

오픈소스 저장소에서 취약점 후보를 찾아 **조율된 공개(coordinated disclosure)**
리포트까지 만드는 다중 에이전트 파이프라인.

목적은 취약점을 "찾는" 것이 아니라, 후보를 사실로 검증하고
**반려당하지 않을 리포트**로 만드는 것이다.

---

## 이 도구가 푸는 문제

AI로 취약점을 찾는 건 쉽다. 문제는 그 결과가 대부분 오탐이라는 것이다.
curl은 AI 슬롭 리포트에 시달리다 2026년 버그바운티를 접었다.

이 파이프라인의 값어치는 속도가 아니라 **오탐과 과장을 걸러내는 것**이다.
두 사이클 동안 교차 검토가 잡아낸 13건은 **전부** 과장·부정확이었고
새 발견은 0건이었다. 그리고 그 13건이 안 걸러졌으면 전부 반려당했을 것이다.

---

## 설치

```bash
./bootstrap.sh /path/to/target-repo [LANG]
```

- 타겟이 git 저장소인지 확인
- 기본 브랜치·언어 자동 감지 → `cvehunt/ENV.md` 생성
- 도구 파일 복사 + 템플릿 배치 + 커밋

`LANG`: `go` `node` `python` `rust` `php` `ruby` `java` `csharp`
(생략하면 매니페스트로 자동 감지)

## 실행 — 순서가 중요하다

**1. 설치** (커밋이 생긴다)

```bash
./bootstrap.sh /path/to/target-repo
```

**2. 워크트리 두 개를 만든다 — 반드시 설치 이후에**

| 이름 | base | 에이전트 |
|------|------|----------|
| `coordinator` | bootstrap이 알려준 기본 브랜치 | 작성자 모델 |
| `review` | 같음 | **검토자 모델 — 작성자와 달라야 한다** |

> **설치 전에 만들면 안 된다.** 워크트리는 만들어진 시점의 커밋에 멈춰 있어서,
> 그 뒤에 커밋된 `cvehunt/`가 따라가지 않는다. 워커가 문서를 못 읽는다.
>
> `review`를 미리 만드는 이유는 모델을 사람이 직접 고르기 위해서다.
> 나머지(`profile` `hunt` `repro`)는 코디네이터가 필요할 때 만든다.

**3. 코디네이터 세션에 한 줄**

```
cvehunt/START.md 를 읽고 그대로 수행해라.
```

`STATE.md`의 `NEXT`를 따라 `human` 또는 `DONE`이 나올 때까지 스스로 돈다.

**4. 사람이 불려나오면** — 재현 승인이거나 제출이다. 아래 표 참조.

**5. 툴킷을 고쳤으면** `bootstrap.sh`를 각 타겟에 다시 돌린다.
   기존 워크트리는 코디네이터의 0단계 동기화가 알아서 가져간다.

## 사람이 등장하는 두 지점

| | 왜 |
|---|---|
| **재현 승인** (S4→S5) | 실제로 파일을 지우거나 서버를 띄운다. 프롬프트의 경로 제약은 부탁이지 강제가 아니다 |
| **제출** | 되돌릴 수 없다. 파이프라인은 절대 제출하지 않는다 |

그 외 S0~S4, S6~S7은 개입 없이 진행한다.

## 단계

```
S0 프로파일링  → TARGET.md       저장소당 한 번. 반복 결함 클래스 0건이면 정지
S1 탐색        → CVE_HUNT.md
S2 게이트 검증 → VERIFY_RESULT.md   G1~G9
S3 외부 모듈   → TRIAGE_EXTERNAL.md
S4 재현 계획   → REPRO_PLAN.md   ★ 사람 승인
S5 재현 실행   → REPRO_RESULT.md
S6 리포트 초안 → REPORT_DRAFT.md
S7 교차 검토   → LOOP_STATE.md    다른 모델이 반증. 최대 3라운드
제출           ★ 사람
```

## 설계 원칙 세 개

**작성자와 검토자는 다른 모델이어야 한다.** 같은 모델의 자기 검토는
"미검증"이라고 적어두고 넘어간 항목을 다시 열지 못한다.

**검토자에게 "검토해줘"가 아니라 "메인테이너가 되어 기각할 이유를 찾아라".**
일반 검토를 시키면 포맷 잡음이 나온다.

**종료 조건은 "둘 다 동의"가 아니라 "미해결 [F] 0건".**
왕복시키면 결국 수렴하는데, 그건 합의로 수렴하는 것이지 정확해져서가 아니다.

## 파일

| 파일 | 역할 |
|------|------|
| `START.md` | 코디네이터 기동. 이 한 줄로 전체가 돈다 |
| `RUN.md` | 파이프라인 설계와 절대 규칙 |
| `ORCHESTRATE.md` | Orca 배선, NEXT 매핑, 워커 계약, 안전 정지 |
| `S0_PROFILE.md` | 타겟 프로파일링 → TARGET.md |
| `PIPELINE.md` | S1~S6 절차와 게이트 |
| `VERIFY.md` | G1~G9 검증 게이트 + 심각도 표현 규칙 |
| `REVIEW.md` | 교차 검토 역할 배정과 조정 규칙 |
| `LOOP.md` | 작성자⇄검토자 왕복과 종료 조건 |
| `LANGUAGES.md` | 언어별 의존성·확장자·sink 패턴 |
| **`LESSONS.md`** | **실전 교훈 15개. 새 저장소 전에 읽어라** |
| `templates/` | 타겟마다 복사되는 빈 틀 |
| `bootstrap.sh` | 설치 |

`ENV.md`(타겟 환경)와 `FINDINGS.md`·`METRICS.md`(인스턴스)는
bootstrap이 타겟에 생성한다. 이 원본 폴더에는 없다.

---

## 툴킷 관리

```
<이 폴더>              ← 원본. 여기서만 고친다
<타겟>/cvehunt/        ← 사본. bootstrap이 복사, git이 추적
```

**타겟 안에도 있어야 한다.** 워커가 워크트리에서 상대경로로 읽고,
git 동기화로 따라가야 하기 때문이다.

툴킷을 고쳤으면 각 타겟에 다시 뿌린다:

```bash
./bootstrap.sh /path/to/target-repo
```

재실행해도 `ENV.md` · `FINDINGS.md` · `METRICS.md`는 덮어쓰지 않는다.

---

## 절대 규칙

- 소스 코드를 수정하지 않는다
- 익스플로잇을 배포하지 않는다. 재현 절차는 리포트에만
- 파괴적 작업은 `ENV.md`의 `REPRO_ROOT` 안에서만
- **남의 인스턴스는 건드리지 않는다.** 자기가 띄운 로컬만
- 파이프라인은 리포트를 제출하지 않는다
